# Static website hosting

This project does **not** need a backend for normal hosting. The deployed site is fully static.

## What to publish

Use the `website/` directory as the web root.

Required files:

```text
website/
├─ index.html
├─ assets/
│  ├─ app.js
│  └─ styles.css
└─ data/
   ├─ site_data.js
   └─ matrix_stats.js
```

Keep the directory structure unchanged because `index.html` loads the assets and generated data with relative paths.

## Hosting

Any normal static host should work, for example GitHub Pages, nginx, Apache, Netlify, Cloudflare Pages, or an equivalent university server.

The server should serve:

```text
website/index.html
```

at the site root.

No Python process, database, API, or server-side application is needed for visitors.

## Updating the data

The files under `website/data/` are generated by the local research pipeline.

If the underlying DB reviewer / DBLP data changes, regenerate the website data locally with:

```powershell
.\run_website.bat
```

Then redeploy the updated `website/` folder.

The large DBLP snapshot, SQLite databases, Python scripts, `.venv`, and `data/` directory are **not needed on the production web server**.

## Quick check before deployment

Open the hosted site and verify that:

- the page loads without 404 errors;
- researcher results appear;
- Crossovers and Publication activity contain data;
- opening a researcher works;
- browser developer tools show no missing `assets/` or `data/` files.
