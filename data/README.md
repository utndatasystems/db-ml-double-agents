# Local data

This directory contains local pipeline inputs, working state, and generated audit/output files.

## Working inputs/state

The normal local working set is:

```text
cidr_reviewers.sqlite
edbt_reviewers.sqlite
icde_reviewers.sqlite
sigmod_reviewers.sqlite
vldb_reviewers.sqlite
entity_resolution.sqlite
dblp_snapshot/
```

The reviewer SQLite databases are scraped DB-service evidence. `entity_resolution.sqlite` is derived from those databases plus the pinned DBLP snapshot, but it is normally kept because rebuilding identity state requires another full DBLP person-record scan and can include applied high-precision decisions.

The pinned snapshot files used by the current code are:

```text
dblp_snapshot/dblp-2026-09-01.xml.gz
dblp_snapshot/dblp-2023-06-28.dtd
```

## Publication corpus

Generate:

```text
dblp_publications_for_db_people.csv
```

with:

```powershell
.\run_dblp_publication_scan.bat
```

This CSV is rebuildable from the resolved PIDs plus the pinned DBLP snapshot, but keeping it avoids repeating the expensive publication scan during normal website work.

## Audit outputs

The following are generated review artifacts:

```text
dblp_name_resolution.csv
dblp_candidates.csv
invalid_reviewer_names.csv
reviewer_scraper_repairs.csv
reports/
backups/
```

They are not website runtime inputs. Reports can be regenerated by the corresponding audit/build commands. Backups are created before guarded identity-resolution writes and should be retained or archived according to your own recovery needs.

## Current affiliations

Fresh entity-resolution builds already store DBLP current/former affiliation fields. For an older entity database, run:

```powershell
.\run_current_affiliation_refresh.bat
```

This requires the pinned local DBLP snapshot and does not change resolved identities.
