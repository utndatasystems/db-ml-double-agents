## A9-1: a changed coverage export deletes lists held by the preceding open summary

**Confirmed bug fixed; medium severity, high confidence.** Root challenged this adjacent boundary while cross-reviewing A8-2. `website/assets/data-coverage.js:24` loads the summary once and `:100` later requests its retained `detailUrl`; the original end of `scripts/data_coverage.py:482` immediately deleted every list not referenced by the new summary after atomic publication. Thus a tab that already loaded the old summary can later receive a 404 for an inspection or CSV list after any changed hash.

Trigger/rule: publish a correction changing a list's title while the prior summary remains open. The prior generation must remain usable through the next changed publication. Expected: both old and new immutable lists remain. Original actual behavior: old list disappears on the second export. `test_changed_summary_retains_previous_lists_and_prunes_only_older_generations` (`tests/test_data_coverage.py:285`) failed on the original source with `AssertionError: False is not true` at the first-generation path-presence check. The fixture uses the real coverage exporter and its existing isolated person/publication input; no production data is changed.

Fix: `scripts/data_coverage.py:481` reads the preceding summary before atomic replacement; `:487`–`:508` collects only its `data/coverage` references and disables cleanup when prior JSON cannot safely identify them; `:514`–`:519` keeps the union of new and preceding filenames, pruning only older generations after promotion. Unchanged asset sets do not advance retention, including summary-wording-only changes; exact repeated text also avoids rewriting the manifest after list repair. Decisions, thresholds and counts are unchanged. Cached pages older than one distinct asset generation remain outside this bounded guarantee; damaged summaries conservatively retain extra files.

Regression coverage: three distinct title generations; identical and wording-only repeats; unchanged old file bytes; an injected atomic-summary promotion failure preserving the old summary/list; malformed old JSON preserving unknown assets; existing damaged-list repair. The older test that demanded immediate deletion now expects one preceding generation before deletion. **All 21 coverage tests pass.** Agent 8 independently reviewed the completed code and reran those 21 tests: approved, no blockers. The baseline saved assets have no demonstrated missing references; actual production loss from a prior open browser session cannot be measured retrospectively. This fixes a demonstrated boundary, not a claim that current saved counts were wrong.
